# ربات تلگرام خلاصه‌ساز روزانه تاپیک‌های گروه (Telegram Forum Daily Summarizer Bot)

این پروژه یک ربات حرفه‌ای و مقیاس‌پذیر برای گروه‌های دارای تاپیک (Forum Supergroups) در تلگرام است. از آن‌جا که Telegram Bot API امکان بازخوانی تاریخچه پیام‌های گذشته گروه را ندارد، این ربات در طول روز پیام‌های ارسالی در تاپیک‌های مختلف را به صورت بلادرنگ دریافت و در پایگاه داده سبک و پرسرعت SQLite ذخیره می‌کند. سپس هر شب رأس ساعت **۰۰:۰۱ بامداد به وقت تهران** (هنگام بسته شدن گروه)، با استفاده از مدل‌های هوش مصنوعی پیشرفته (Google Gemini یا API سازگار با OpenAI)، پیام‌های هر تاپیک را به زبان فارسی سلیس و در قالب یک ساختار منظم و دسته‌بندی‌شده تلخیص کرده و در گروه منتشر می‌کند تا اعضایی که در طول روز آفلاین بوده‌اند، بتوانند در کمترین زمان ممکن از مباحث آگاه شوند.

## ویژگی‌های کلیدی
- **کاملاً ناهمگام (Async):** توسعه داده شده با Python 3.11+، Aiogram 3.x، Aiosqlite و HTTPX.
- **پردازش متون بسیار طولانی با Map-Reduce:** در صورتی که حجم پیام‌های روزانه یک تاپیک از آستانه ۲۴,۰۰۰ کاراکتر فراتر رود، متن به قطعات خطی تقسیم، خلاصه‌های جزئی استخراج و در نهایت در یک خلاصه یکپارچه ادغام می‌شوند.
- **تفکیک هوشمند پیام‌ها بر اساس محدودیت تلگرام:** شکستن ایمن پیام‌های بالای ۴۰۰۰ کاراکتر بدون خراب شدن یا باز ماندن تگ‌های HTML تلگرام (`<b>`, `<i>`, `<a href>`, `<code>`, `<blockquote>`).
- **فیلتر نویز فارسی و انگلیسی:** حذف خودکار احوالپرسی‌های روزمره، کلمات کوتاه، استیکرها، گیف‌ها، پیام‌های صوتی و تصویری فاقد کپشن و پیام‌های کم‌ارزش.
- **پشتیبانی از دو حالت پایش تاپیک‌ها:**
  - **لیست سیاه (Blacklist - پیش‌فرض):** تمام تاپیک‌ها پایش می‌شوند مگر آن‌هایی که حذف شده باشند.
  - **لیست سفید (Whitelist):** فقط تاپیک‌هایی که صراحتاً اضافه شده‌اند پایش می‌شوند.
- **پشتیبانی از دو حالت مقصد خلاصه‌ها:**
  - **ارسال در هر تاپیک (Per Topic - پیش‌فرض):** خلاصه هر تاپیک در خودش ارسال می‌شود.
  - **ارسال تجمیعی (Aggregate):** خلاصه تمامی تاپیک‌ها با ذکر نام تاپیک مبدا در یک تاپیک مشخص ارسال می‌گردد.
- **مقاومت در برابر قطعی و خطا (Resilience):** مجهز به مکانیزم تلاش مجدد نمایی (Exponential Backoff) برای خطاهای موقت شبکه و محدودیت نرخ (Rate Limit 429/5xx).
- **پشتیبانی از تقویم جلالی:** ثبت و درج تاریخ شمسی و روزهای هفته به فارسی روان به همراه تاریخ میلادی در سربرگ خلاصه‌ها.
- **مدیریت خطاهای ارسال:** در صورت خطای تجزیه موجودیت‌های تلگرام، خلاصه به صورت خودکار با حذف تگ‌های نامعتبر به عنوان متن ساده ارسال می‌شود تا از توقف فرآیند جلوگیری شود.

## راه‌اندازی گام به گام ربات

### ۱. ساخت ربات در BotFather و تنظیمات حریم خصوصی
۱. در تلگرام به آیدی `BotFather@` پیام دهید و دستور `/newbot` را ارسال نمایید.  
۲. نام و نام کاربری ربات را انتخاب کرده و **توکن ربات (BOT_TOKEN)** را کپی کنید.  
۳. **بسیار مهم (حالت حریم خصوصی):** تلگرام به صورت پیش‌فرض پیام‌های گروه‌ها را به ربات‌های معمولی نشان نمی‌دهد. برای حل این موضوع یکی از دو کار زیر را حتماً انجام دهید:
   - **روش اول (توصیه‌شده):** در BotFather دستور `/setprivacy` را ارسال کنید، ربات خود را انتخاب کرده و آن را روی **Disable** تنظیم کنید. با این کار ربات می‌تواند پیام‌های ارسالی تمام اعضا را مشاهده کند.
   - **روش دوم:** در صورت عدم تغییر این تنظیم، باید ربات را در سوپرگروه به عنوان **مدیر (Administrator)** اضافه کنید.

### ۲. افزودن ربات به سوپرگروه و مجوزها
۱. ربات را به سوپرگروه مورد نظر خود اضافه کنید.  
۲. مجوزهای لازم برای ربات:
   - مشاهده پیام‌ها (View Messages)
   - ارسال پیام در تاپیک‌ها (Send Messages)
   - حذف پیام‌ها (Delete Messages - اختیاری برای پاک کردن دستورات مدیران)

### ۳. دریافت کلید API گوگل جمینای
۱. وارد سایت [Google AI Studio](https://aistudio.google.com/) شوید.  
۲. با حساب کاربری گوگل خود لاگین کرده و روی دکمه **Get API key** کلیک کنید.  
۳. کلید ایجاد شده را کپی کرده و در فایل `.env` قرار دهید.

## تنظیم متغیرهای محیطی (.env)
یک کپی از فایل `.env.example` با نام `.env` ایجاد کنید:
```bash
cp .env.example .env
```
محتوای فایل `.env` را به شکل زیر تکمیل کنید:
```ini
# توکن ربات دریافتی از BotFather
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrSTUvwxYZ

# شناسه‌های عددی مدیران ربات (جدا شده با کاما)
ADMIN_IDS=123456789,987654321

# شناسه گروه مجاز (در صورت خالی بودن، ربات در هر گروه تاپیک‌داری کار می‌کند)
ALLOWED_CHAT_IDS=-100123456789

# پروکسی اختیاری (HTTP یا SOCKS5)
PROXY_URL=

# ارائه‌دهنده هوش مصنوعی: gemini یا openai
AI_PROVIDER=gemini

# تنظیمات گوگل جمینای
GEMINI_API_KEY=AIzaSyYourGeminiApiKeyHere
GEMINI_MODEL=gemini-2.5-flash

# تنظیمات OpenAI (در صورت استفاده از AI_PROVIDER=openai)
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini

# آستانه‌ها و محدودیت‌ها
MIN_MESSAGES_PER_TOPIC=5
MIN_MESSAGE_LENGTH=3
CHUNK_MAX_CHARS=24000

# زمان‌بندی اجرای شبانه به وقت تهران
SUMMARY_TIME_HOUR=0
SUMMARY_TIME_MINUTE=1
TIMEZONE=Asia/Tehran

# مدت نگهداری پیام‌ها در دیتابیس (روز)
RETENTION_DAYS=7

# تاخیر بین ارسال پیام‌ها (ثانیه) برای جلوگیری از لیمیت تلگرام
SEND_DELAY_SECONDS=1.8

# حداکثر تلاش مجدد در صورت خطای API
AI_MAX_RETRIES=3

# مسیرها
DB_PATH=data/bot.db
LOG_DIR=logs
LOG_LEVEL=INFO
```

## نصب و اجرای محلی

۱. کلون یا ورود به پوشه پروژه:
```bash
cd tg-daily-summarizer
```

۲. ایجاد محیط مجازی پایتون و فعال‌سازی آن:
```bash
python3 -m venv .venv
source .venv/bin/activate  # در لینوکس و مک
# یا در ویندوز:
# .venv\Scripts\activate
```

۳. نصب وابستگی‌های پین‌شده:
```bash
pip install -r requirements.txt
```

۴. اجرای تست‌های آفلاین:
```bash
pytest -v
```

۵. اجرای ربات:
```bash
python -m bot.main
```

## پیکربندی پروکسی
در صورت مسدود بودن دسترسی مستقیم به سرورهای تلگرام یا سرویس هوش مصنوعی، می‌توانید متغیر `PROXY_URL` را مقداردهی نمایید. این تنظیم به طور همزمان روی نشست تلگرام و کلاینت هوش مصنوعی اعمال می‌شود:
- **پروکسی SOCKS5:**
  ```ini
  PROXY_URL=socks5://127.0.0.1:1080
  # یا در صورت نیاز به احراز هویت:
  PROXY_URL=socks5://user:password@127.0.0.1:1080
  ```
- **پروکسی HTTP:**
  ```ini
  PROXY_URL=http://127.0.0.1:8080
  ```

## استقرار با Systemd
برای اجرای خودکار، دائمی و بدون وقفه ربات روی سرورهای ابری اوبونتو/دبیان:

۱. فایل سرویس موجود در مسیر `deploy/tg-summarizer.service` را ویرایش کرده و نام کاربری و مسیرهای مربوطه را با اطلاعات سرور خود جایگزین کنید:
```ini
[Unit]
Description=Telegram Forum Daily Summarizer Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/tg-daily-summarizer
EnvironmentFile=/home/ubuntu/tg-daily-summarizer/.env
ExecStart=/home/ubuntu/tg-daily-summarizer/.venv/bin/python -m bot.main

Restart=always
RestartSec=5s
LimitNOFILE=65535
StandardOutput=journal
StandardError=journal
SyslogIdentifier=tg-summarizer

[Install]
WantedBy=multi-user.target
```

۲. کپی فایل به پوشه سیستم‌دی و فعال‌سازی سرویس:
```bash
sudo cp deploy/tg-summarizer.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tg-summarizer
```

۳. مشاهده لاگ‌های زنده:
```bash
journalctl -u tg-summarizer -f
```

## جدول دستورات مدیریتی ربات
تمامی دستورات زیر صرفاً توسط **مدیران گروه یا کاربران قید شده در ADMIN_IDS** و در محیط تاپیک‌های گروه قابل اجرا هستند:

| دستور | توضیحات |
| :--- | :--- |
| `/status` | نمایش وضعیت کلی سیستم، حالت پایش، مقصد ارسال، تعداد پیام‌های انباشته، زمان اجرای بعدی و مدل فعال |
| `/topics` | نمایش لیست تمامی تاپیک‌های شناخته‌شده، وضعیت پایش آن‌ها و تعداد پیام‌های ذخیره‌شده امروز |
| `/add_topic` | افزودن تاپیک جاری به لیست تاپیک‌های تحت نظارت خلاصه‌سازی |
| `/remove_topic` | خروج تاپیک جاری از لیست تاپیک‌های تحت نظارت |
| `/mode whitelist` | تغییر حالت پایش به لیست سفید (تنها تاپیک‌های تایید شده با add_topic پایش می‌شوند) |
| `/mode blacklist` | تغییر حالت پایش به لیست سیاه (تمام تاپیک‌ها به جز موارد حذفی پایش می‌شوند - پیش‌فرض) |
| `/set_destination [لینک\|شناسه]` | تنظیم تاپیک مقصد تجمیعی تمامی خلاصه‌های گروه (با ارسال بدون آرگومان در خود تاپیک یا ارسال لینک تاپیک/پیام یا شناسه عددی) |
| `/reset_destination` | بازگرداندن مقصد ارسال به حالت پیش‌فرض (ارسال خلاصه در همان تاپیک مربوطه) |
| `/summary_on` | فعال‌سازی سامانه خلاصه‌سازی برای این گروه |
| `/summary_off` | غیرفعال‌سازی موقت سامانه خلاصه‌سازی برای این گروه (شنونده ذخیره نمی‌کند و اجرای شبانه متوقف می‌شود) |
| `/summarize_now` | اجرای فوری و دستی خلاصه‌سازی برای تاپیک جاری (پیام‌ها پس از ارسال موفق از دیتابیس پاک می‌شوند تا فضا اشغال نشود) |
| `/summarize_now keep` | اجرای آزمایشی خلاصه‌سازی تاپیک بدون حذف پیام‌ها (پیام‌ها برای اجرای شبانه یا تست‌های بعدی محفوظ می‌مانند) |
| `/summarize_all [keep]` | اجرای دستی خلاصه‌سازی برای تمامی تاپیک‌های فعال گروه به صورت متوالی |
| `/help` | نمایش پیام راهنمای فارسی دستورات |

## نحوه تست سریع
برای تست اولیه ربات بدون دستکاری داده‌های واقعی یا منتظر ماندن تا ساعت ۰۰:۰۱ شب:
۱. در یکی از تاپیک‌های گروه چند پیام تستی (بیشتر از ۵ پیام معنادار) ارسال کنید.  
۲. دستور زیر را در همان تاپیک ارسال نمایید:
   ```
   /summarize_now keep
   ```
۳. ربات پیام‌ها را جمع‌آوری کرده، از طریق جمینای خلاصه را با فرمت زیبای تلگرام تولید و در تاپیک ارسال می‌کند. به دلیل استفاده از گزینه `keep`، پیام‌ها در دیتابیس علامت خلاصه‌شده نمی‌خورند و می‌توانید بارها خروجی را بررسی و تنظیم نمایید.

## نگهداری و پاک‌سازی داده‌ها
- **اجرای شبانه:** هر شب در ساعت ۰۰:۰۱ بامداد به وقت تهران اجرا شده و پیام‌های روز قبل (تقویم تهران) را خلاصه می‌کند.
- **پاک‌سازی خودکار (Cleanup):** هر روز ساعت ۰۳:۳۰ بامداد، پیام‌های قدیمی‌تر از ۷ روز (قابل تنظیم در `RETENTION_DAYS`) به صورت خودکار از پایگاه داده پاک می‌شوند.
- **بهینه‌سازی پایگاه داده:** دستور `PRAGMA optimize` روزانه اجرا شده و در روزهای شنبه، چنانچه حجم فایل پایگاه داده از ۵۰ مگابایت بیشتر باشد، دستور `VACUUM` برای آزادسازی فضای دیسک اجرا می‌گردد.

## راهنمای عیب‌یابی

### ۱. ربات پیام‌های ارسالی اعضا را نمی‌بیند یا ذخیره نمی‌کند
- **علت:** قابلیت Privacy Mode در تلگرام به صورت پیش‌فرض فعال است.
- **راه‌حل:** به `BotFather@` مراجعه کرده، دستور `/setprivacy` را ارسال کنید و وضعیت را روی **Disable** بگذارید؛ یا اینکه ربات را به عنوان ادمین گروه با دسترسی خواندن پیام‌ها تعیین کنید.

### ۲. خلاصه برای تاپیک ارسال نمی‌شود
- **علت اول:** تعداد پیام‌های ذخیره‌شده کمتر از حد نصاب `MIN_MESSAGES_PER_TOPIC` (پیش‌فرض ۵ عدد) است.
- **علت دوم:** تاپیک در حالت لیست سیاه حذف شده یا در حالت لیست سفید اضافه نشده است. وضعیت را با دستور `/topics` بررسی کنید.
- **علت سوم:** کلید `GEMINI_API_KEY` اشتباه است یا سهمیه مصرف اکانت به اتمام رسیده است. لاگ‌ها را در فایل `logs/bot.log` بررسی کنید.

### ۳. خطای محدودیت نرخ تلگرام (Flood Control / RetryAfter)
- ربات مجهز به سیستم مکث خودکار در صورت وقوع `TelegramRetryAfter` است و پیام‌ها را با تاخیر کنترل‌شده ارسال می‌کند. در صورتی که تعداد تاپیک‌های شما بالاست، می‌توانید مقدار `SEND_DELAY_SECONDS` را در فایل `.env` افزایش دهید (مثلاً ۲.۵ ثانیه).

### ۴. خطای اتصال به سرور یا پروکسی
- از صحت کارکرد پروکسی مطمئن شوید (`curl -x socks5://127.0.0.1:1080 https://api.telegram.org`). در صورت عدم نیاز به پروکسی، متغیر `PROXY_URL` را در فایل `.env` کاملاً خالی بگذارید.
